# 从原第九轮恢复 S1024/N1，缩小每次更新

2026-10-06。按最新决定，从原 S1024/N1 连续混合训练第九轮、9500 步创建独立分支，配置为 `configs/entity_attention_v1/hybrid_fork_s1024_n1.json`。模型、AdamW moments/步数及训练 RNG 接续，不重新离线学习。原 run、N2 分支及其进程和数据保留。

本配置采用 **200 局 / 100 步**：把原来的 1000 局 / 500 步拆成五次采集和更新，在相同累计新局数下保持相同总更新量，每 100 步刷新一次采集模型。此前 N2 分支的 100 局 / 100 步把每局更新量加倍，且同时改变了教师 S/N、回放窗口；不能用它单独判断更新粒度或新局数的影响。

同日按最新要求将在线回放上限从6000改为**3000局**，限制教师数据的年龄。原6000局配置及只初始化验证保留为历史记录；本文以下3000局方案为现行配置。这意味着本次同时改变更新周期与在线窗口，不能再称为与原run仅一个变量不同。

2026-10-06最新状态：用户完成50个新轮次、累计14500步后停止训练。对固定theta_5000的第35/40/45/50轮score为79%/73.5%/72.5%/71.5%，均为100局有效面板；点估计回落，但配对差值区间仍较宽。第31轮起纯在线训练20轮，在该面板上没有建立稳定增益，不能把第35轮峰值归因于退出旧离线数据。新的[强锚点补测](../../artifacts/entity_attention_strong_anchor_20261006/README.md)对同一PPO 5.5M测得原第9轮63.75%、第50轮61.75%，各200局有效；50−9配对95%区间为−11.75～+7.50个百分点，不能确认退化，也未确认提升。当前已实现[分头窗口与detach value续训](entity_attention_split_training_zh-CN.md)，从第50轮独立分支，policy近4轮、value3000局/近期50%、独立clip；有限验证完成，正式长训未启动。旧[最新单轮配额设计](entity_attention_fresh_share_zh-CN.md)保留为历史候选。

第31轮采集曾于2026-10-06 13:23被系统RAM OOM杀死；跨轮缓存淘汰、纯在线离线缓存退出及执行预算覆盖已修复，用户随后恢复并完成至50轮。[内存修复与窗口分析](../../artifacts/entity_attention_memory_window_20261006/README.md)保留修复时截至30轮的历史证据。Graph **B[16,32,64,128,200]、批次上限200**用于后续正式轮次；S1024/N1、200局/100步、3000局窗口和原离线退出日程未改变。

## 已有证据与本次对照范围

目前没有同教师、同窗口、同更新/新局数比的 100 局与 1000 局训练对照，所以不能认定退化由每轮新局数不足造成。N2 分支新轮 10/20/30 的固定对手得分为 68.0%/63.5%/62.5%，起点为 69.5%；新轮 20 在线池已经含最近 2000 局新分支数据，训练并非只使用刚采集的 100 局。这个趋势值得检查，但没有隔离教师质量、窗口、重复使用量与更新粒度。

[原第 3、9 轮的 100 步与 500 步对照](../../artifacts/entity_attention_100_vs_500_20261005/README.md)保持同一轮 1000 局采集不变：第九轮得分为 69.0% 与 69.5%，500−100 的配对 95% 区间为 −10.5～+11.0 个百分点。它没有检验减少新局数，也没有证明长期 100 步已足够。该报告建议先保持更新/新局数比，本配置采用这一对照方式，不把 200 局解释为已验证的最优局数。

[有限 S/N 筛选](../../artifacts/entity_attention_search_screen_20261005/README.md)推荐 N2 时仅依据冻结权重棋力、目标敏感性和短窗口成本，没有证明长期训练收益。此次回归 N1 是新的训练选择，不代表已证明 N2 实现错误。

### 数据来自哪些教师

继承的3000局不是9500步模型生成的：

| 继承采集轮次 | 完整局数 | 实际生成教师 | 搜索配置 |
| --- | --- | --- | --- |
| 原第7轮 | 1000 | 原8000步模型 | S1024/N1 |
| 原第8轮 | 1000 | 原8500步模型 | S1024/N1 |
| 原第9轮 | 1000 | 原9000步模型 | S1024/N1 |

新轮1由9500步模型采集，新轮2由9600步模型采集，之后每100步换教师。第15个新轮次后，池内为新轮1～15的3000局，教师为9500～10900步；此后始终保留最近15个采集教师。训练前，最旧教师与当前采集教师差14次更新、1400步；本轮100步更新后，与当前模型差1500步。这是固定200局/100步且不回滚时的稳态年龄上限。

过渡期间原教师每隔500步更新，不能按新轮次的100步间隔计算其年龄；最旧继承教师在被淘汰前，最多与本轮更新后模型相差1900步。3000局上限通过本方案固定的200局/教师约束来源年龄，当前实现仍按采集时间FIFO，而不是独立的“教师最多落后多少步”筛选器。以后改变每轮采集量或更新量，必须重新计算该年龄，不把3000当作通用最优容量。

还有一个独立来源：原离线数据为旧Deep-Sets训练轨迹的十轮数据，来自十个采集教师，并非当前attention教师的最近15个版本。当前配置仍保持其原退出日程：前5新轮每batch取64个离线局面，此后到第30新轮取32个，第31轮起归零。**3000局只限制在线池，不能把整个训练batch都称为最近15个教师的数据。**

离线日程按原计划剩余采集量换算：原第 10 轮的最后 1000 局使用离线配额 64，再 5000 局使用配额 32，然后纯在线。在线池每轮加入 200 局，按采集轮次/game_id顺序FIFO移出最旧200局；历史文件不删除。

| 分支新轮次 | 累计新局数 | 在线池继承 / 新分支完整局数 | 每 batch 原离线 / 在线局面 |
| --- | --- | --- | --- |
| 1 | 200 | 2800 / 200 | 64 / 192 |
| 5 | 1000 | 2000 / 1000 | 64 / 192 |
| 6 | 1200 | 1800 / 1200 | 32 / 224 |
| 10 | 2000 | 1000 / 2000 | 32 / 224 |
| 15 | 3000 | 0 / 3000 | 32 / 224 |
| 16～30 | 3200～6000 | 0 / 最近3000局 | 32 / 224 |
| 31 及以后 | 6200 及以后 | 0 / 最近3000局 | 0 / 256 |

在线配额在整个在线池的 train positions 上均匀、有放回抽样，不强制 batch 中最新 200 局的份额，也不按对局或教师等权；局长与整局留出会影响不同教师的实际抽样比例。原离线十轮数据的配额在新轮31归零，在线池在新轮15完全由本分支生成；本分支与继承在线数据均使用N1。较小窗口提高新近教师的份额，同时减少历史局面多样性，棋力收益仍需训练检验。

`replay_snapshot.json`记录当前teacher的路径、SHA和训练步数，以及各游戏的来源轮次/run_id；各来源轮次的`selfplay/manifest.json.checkpoint_identity`可核对实际生成教师。`replacement`记录实际位置比例，`source_usage.json.online_replacement.actual_draws`和每步`source_positions`记录继承/新分支抽样量，但没有按每个教师单独加权。此次[3000局验证摘要](../../artifacts/entity_attention_hybrid_s1024_n1_20261006/verification_replay3000.json)列出继承教师身份与按固定计划推算的教师年龄。检查学习趋势时比较同一固定对手、固定验证集，并以累计新局数、累计更新及采集时间对齐。

## 启动与恢复

从仓库根目录执行，用新的正式输出目录：

以下`--forever`没有预设轮数或训练步数上限，会一直采集、更新最新教师；手动中断或运行错误才停止。3000局是在线训练窗口上限，不是全程累计采集量，也不是原始NPZ文件的磁盘保留上限。手动中断后用resume接续。

```bash
conda run --no-capture-output -n splendor env PYTHONPATH=src TORCHINDUCTOR_COMPILE_THREADS=2 python -u -m splendor.hybrid_train \
  --config configs/entity_attention_v1/hybrid_fork_s1024_n1.json \
  --fork-from runs/entity_attention_hybrid_static_graph_seed1 --fork-round 9 \
  --output runs/entity_attention_hybrid_s1024_n1_from_round9_seed1 \
  --forever --replay-cache-mib 8192
```

新建分支时，有限运行可把`--forever`改为`--online-rounds 15`：完成3000新局/1500更新，从9500到11000步，在新轮5、10、15评测，此时在线池全部由新分支生成。它不是默认停止点。已有分支恢复时去掉fork参数；以下命令现在会从第50轮之后继续，不重新离线，仍使用原均匀采样。这不是新最新份额方案的启动命令：

```bash
conda run --no-capture-output -n splendor env PYTHONPATH=src TORCHINDUCTOR_COMPILE_THREADS=2 python -u -m splendor.hybrid_train \
  --config configs/entity_attention_v1/hybrid_fork_s1024_n1.json \
  --output runs/entity_attention_hybrid_s1024_n1_from_round9_seed1 \
  --resume --forever --replay-cache-mib 8192
```

`--online-rounds`为分支自创建后的绝对完成轮数。冻结JSON恢复仅允许调整`selfplay.execution.max_batch_size`和`batch_buckets`，训练、教师搜索、混合日程、窗口及其他字段仍要求一致；新增`--replay-cache-mib`独立覆盖执行预算，不改JSON、数据或checkpoint。已有采集manifest的轮次沿用该轮原尺寸直到采集完成，新开始的轮次才采用新尺寸；不会重写旧manifest或NPZ。根目录`config.json`保留初始化配置，每次会话的`source/<session>/identity.json.collection_execution`记录请求的执行配置，`replay_cache_capacity_bytes`记录实际缓存预算，`frozen_config_sha256`记录原配置身份，每轮有效执行参数见其采集manifest。

原NPZ通过路径引用，必须保留父run与离线数据源。已有N2分支使用独立输出目录，其运行状态不会被以上命令覆盖。本机单GPU，正式新任务应与已有训练错开运行。
