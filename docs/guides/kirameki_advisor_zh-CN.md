2026-10-30：连接已有浏览器中的 `https://kirameki-lab.com/play/game`，读取本人可见盘面，用固定 policy 在线第9轮权重推荐，由用户手动执行。支持非排位双人对局；不提交动作、不导航、不修改网站设置。网站[条款](https://kirameki-lab.com/terms)禁止排位中的外部程序辅助，脚本遇到排位会等待。

上段及下文“只读”描述适用于 `splendor.kirameki_live`。2026-10-31按用户授权另加 `splendor.kirameki_autoplay`，该入口会操作非排位对局并在终局后重开；原只读命令保持只推荐。

## 非排位自动对弈

先在网站菜单取消 **Ranked game**，选择 **Gem Deity／宝神**；也可以接入已经开始的同等级非排位棋局。停止旧推荐器后，从仓库根目录执行：

```bash
conda run --no-capture-output -n splendor env PYTHONPATH=src python -u -m splendor.kirameki_autoplay
```

默认固定第9轮权重，CUDA、随机节点单树 **S65536N1，总预算65536**、`leaf_batch_size=32`、compiled/native-cudagraph、visits选点；沿用无根噪声／无CPW设置。每个需要搜索的支付或归还条件决策另用相同预算。32是结合用户对搜索质量的关注采用的保守工程折中，尚未通过正式棋力对照证明优于64。旧64档的测速及历史推荐保留在[加速报告](../../artifacts/single_tree_batch_20261031/README.md)。

默认持续对弈，Ctrl-C停止；`--games 10`完成本次接入后观察到的10局后停在终局页，`--once`只执行并确认一手。接入时已经结束的旧局会保存并重开，不计入本次局数。每次开始／重开均把先后手设为 **Random**，确认网站设置生效后才点开始；保持菜单中的时钟设置。脚本不代选对手或切换排位，发现排位／对手等级不符时等待用户调整。默认等级ID为`bga1000-v5`，可用`--opponent-level`显式指定其他等级。

实现通过网站现有棋盘回调与动作面板提交，支持拿三色／双同色、市场／盲保留、市场／保留牌购买、精确支付（包括主动多付黄金）、逐枚归还、贵族选择和唯一合法pass。保留造成超限时先执行网站保留动作，再处理独立归还阶段；拿筹码附带的归还按网站原子USI一起确认。缺金保留的提示通过原面板确认。

每次准备和提交前核对本人回合、非排位、目标对手、完整安全快照与当前合法USI；搜索期间变盘则丢弃。提交后要求网站棋谱在原前缀后出现**相同USI**，允许对手已紧接着回复。结果不明、超时、棋谱不符或页面切走时停止，不自动重发。若发生此类停止，请先检查网页棋谱，再刷新原棋局并重跑。浏览器前端更新导致回调不匹配时明确失败，不猜测落子。

记录默认在`runtime/kirameki_autoplay/`，不进Git：`session.json`记录参数／权重SHA／调用源码SHA／启动命令；`games/<局标识>/decisions/`保存每次安全快照、模型输入和建议，`events.jsonl`保存准备／确认／失败事件，`result.json`保存网站终局结果、完整USI棋谱和安全终局快照；`summary.json`为本次会话胜平负，`latest.json/md`为最新已确认动作。网站非排位记录没有独立ID，使用其公开开始时间派生本地局标识，不读取牌序种子。会话配置和汇总在重启时更新，各局目录保留。

有限真实验证：一局首手greedy、后续S128N1／batch16的工程对局共60条网站USI正常终局，网站结果15:14；其间修复支付选择后确认面板尚未更新的时序问题，失败前没有发出该动作，刷新后继续原局。另验证终局→菜单→Random→重开，以及正式S65536N1／batch32／CUDA Graph的一手实际提交，搜索约4.3秒，启动预热11.0秒单列。最终相关回归74项通过。这些是工程验证，不作为棋力结论。原件及`verification.json`位于`runtime/kirameki_autoplay_20261031_smoke/`；动作适配／非排位检查／Random检查／支付按钮延迟／重复提交阻止／棋谱确认与终局保存由`tests/test_kirameki_autoplay.py`覆盖。

## 当前推荐：单树批量叶子与 CUDA Graph

2026-10-31接入随机节点单树内批量叶子和已有编译推理。当前机器推荐以下命令；先停止旧推荐器，再从仓库根目录运行，新进程会加载已原子替换的原生扩展：

```bash
conda run --no-capture-output -n splendor env PYTHONPATH=src python -u -m splendor.kirameki_live --search-backend native_chance --device cuda --search-workers 1 --determinizations 1 --simulations-per-world 65536 --leaf-batch-size 32 --inference-mode compiled --compile-mode native-cudagraph
```

这是**S65536N1，总预算65536，单棵随机节点共享树**；32是最多同时在途的模拟数，不是世界数，不额外乘预算。按2026-10-31后续讨论从原速度优先的64调整为保守的32，尚无棋力优劣证明。沿用固定第9轮权重、无CPW／根噪声、最高访问数选点。模型权重与身份见下文。购买后的有选择支付、超限归还仍各自搜索同样预算；唯一合法动作零模拟。

首次编译／Graph预热在监听前进行，冷编译可能约一分钟；磁盘编译缓存命中后仍需建立本进程Graph。之后持续复用实际推理缓冲。首次编译、启动预热和每步搜索耗时分开统计；不要把冷启动计入稳定单步延迟。

原生树通过不计分的临时访问占位收集叶子；每个在途模拟拥有独立编号、隐藏样本及随机翻牌流。相同待评估信息节点合并一次前向，按各自路径回传，每批完成后再选下一批。临时访问不写入最终N/W，结束时必须归零。批量改变回传时序，**不保证与逐叶串行选点一致**；8192次筛选中确有改选，65536次三个真实盘面检查的首选均一致，尚无正式棋力对照。

本机三个主行动根的65536次预热后时间：串行GPU编译约18.3–19.1秒，batch32约3.14–3.56秒，batch64约2.82–3.20秒，batch128约2.68–3.12秒。32／64／128最高碰撞率分别4.1%／8.1%／16.3%；当前用32减少回传延迟及碰撞，64保留为偏重速度的可选项，128的额外收益较小。8192次可优先考虑16；同预算搜索效率和同耗时棋力仍需分别验证。完整结果、源码冻结与口径见[工程报告](../../artifacts/single_tree_batch_20261031/README.md)。

命令兼容性：未指定新参数时保留旧逐叶／eager行为。`--leaf-batch-size`只适用于`native_chance`；`native-cudagraph`要求CUDA、compiled和单搜索进程，编译失败直接报错。CPU可使用批量叶子和eager；GPU多世界旧入口也可显式使用compiled。JSON增加叶子批量、碰撞数、在途／临时访问、每次搜索runner统计及进程累计推理统计。

## 按世界等权平均Q选点

默认 `--root-q-min-visits 32 --root-q-candidates 8`。设每世界预算B、根动作数A、K=min(A,8)、门槛m=32：

1. 每个世界先按原PUCT搜索B−K×m次。默认S4096时，根候选至少8个则先搜3840次，预留256次。
2. 汇总全部世界的初始根访问数，取前K名作为共同补评候选；并列按根先验、候选顺序确定。CPU多进程在此同步，所有进程使用同一份候选，不各自挑选。
3. 在原树上继续搜索：优先将共同候选的访问数补到每个世界至少m次；满足后，剩余预算继续原PUCT。每世界最终仍严格B次，原有节点、访问数及收益累计保持，不重建世界。
4. 所有在每个世界都达到m次的动作均有资格，包括共同补评候选之外自然达到门槛的动作。各世界先分别计算Q=W/N，再对世界等权平均；选均值最大者，并列按总访问数、根先验、候选顺序确定。

任何世界访问不足的动作都不能跳过该世界后参与均值选点；零访问Q记为null，不补0。补评保证共同候选具有资格。要求B>K×m，否则明确报错；不会静默降低门槛或额外增加总预算。小预算smoke须显式降低m／K；唯一合法动作仍直接返回，零模拟。

这是网站推荐的选点配置。通用 `MCTSConfig` 的默认行为和历史评测／采集配置保持原语义；新增原生暂停／补评接口仅在显式调用时生效。训练用访问分布并未改成Q分布。

终端前三名现在按合格动作的等权Q排序，并显示每世界最低访问数及原始访问份额。JSON新增：

- `selection_rule: world_mean_q`、`root_q_selection`：门槛、共同补评候选、全部合格候选、各动作等权Q、初始阶段访问矩阵，以及同一次搜索最终访问首选与Q首选是否不同。
- `per_world_root_visit_counts`、`per_world_root_value_sums`：全部动作、全部世界的原始累计量，可复算全候选统计。
- 候选的 `world_mean_q_actor`、`per_world_visits`、`per_world_q_actor`、`eligible_for_q_selection`。历史 `search_q_actor` 仍是按访问次数混合的Q，不能当作世界等权Q。

`changed_from_visit_choice` 比较的是**本次包含补评的搜索**中两个选点规则，不代表与此前纯PUCT搜索的因果差异；补评本身也改变了预算分配。每世界32次是工程门槛，并非置信度保证；短验证不证明棋力优于旧规则。

### 推荐时显示预估胜率

终端、离线 `--snapshot` 输出及 `latest.md` 均显示本人视角的预估胜率，JSON 保存 `estimated_win_rate_actor`（0–1）和 `win_rate_basis`（估值来源）。沿用胜=1、和=½、负=0的口径，以 `clamp((x+1)/2,0,1)` 换算：

- `world_mean_q_actor`：独立世界等权Q选点时，取本次推荐动作的世界等权Q。
- `search_q_actor`：按访问数选点时（包括 `native_chance`），取本次推荐动作的搜索Q，即该动作全部世界收益和除以访问数。
- `value_actor_raw`：greedy或唯一候选零模拟、没有动作搜索Q时，使用当前局面的网络V，并在输出中明确标为“网络V”。不调用模型的强制跳过／唯一贵族不提供估值。
