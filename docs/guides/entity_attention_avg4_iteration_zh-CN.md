# 行为搜索复用的M4连续训练

2026-10-09追加标签已改为8个CPU搜索worker＋单GPU owner，并通过有限验证。截至本次核对，已完成12轮／2400局／1200更新步，最新17700步；第2/4/8轮对战完成，第12轮对战中断在61个完整pair。完整面板均未确认超过冻结起点，原实验保持停止。新增[固定数据历史采样与梯度实验](../../artifacts/entity_attention_policy_history_20261009/README.md)比较A/B/C及0/50/200/500步，独立执行，不改变正式日程。配置为[`iteration_avg4_behavior_20261009.json`](../../configs/entity_attention_v1/iteration_avg4_behavior_20261009.json)，准备记录见[实验交付物](../../artifacts/entity_attention_avg4_behavior_20261009/README.md)。

## 标签与历史池

从原分头训练第20轮完成后的16500步checkpoint分支，继承模型、AdamW状态与训练采样RNG。每轮仍采200局、训练100步、学习率`1e-4`，共16轮／3200新局／1600更新步，最终18100步。

每个可搜索真实决策根保留行为搜索作为第1份标签，再用同一冻结教师做3次独立完整S1024/N1搜索。世界抽样和根噪声使用独立派生种子；每份仍使用原`c_puct=1.5`、根噪声比例0.25等搜索参数。四份访问目标取算术平均，只替换监督policy target。行为动作、原始访问计数、终局value标签、开局温度策略和200局的实际轨迹保持原样；非搜索决策维持原目标与零policy权重。追加搜索选出的动作不会进入真实轨迹。

这是**行为1份＋追加3份，总4份**。[旧平均标签短训](../../artifacts/entity_attention_target_averaging_20261007/README.md)是额外搜4份，另有原行为搜索，总搜索成本约5倍；其收益不能直接视为本分支已验证的结果。

沿用历史池：policy取最近4轮约800局，batch256；value取3000局FIFO，batch256中128个位置来自最近4轮、128个来自更旧历史。位置抽样规则、policy/value独立clip1、value对encoder的detach均保持原配置。

旧数据不重标注，仍使用其原单次目标；新数据使用M4。前三轮policy池中M4占比大致为1/4、1/2、3/4，第4轮起全部来自M4；实际按各轮train位置数加权，并不保证严格等比例。每轮`replay_snapshot.json`保存期望比例，`source_usage.json`保存实际M4抽样位置数及比例。这些计数包括被抽到但policy权重为零的决策，不等于有效policy梯度数。

原始NPZ不修改；四份目标、均值、额外访问计数及种子写入相邻`policy_labels/`，按manifest和SHA冻结。未来继承本分支时也冻结活动历史的标签manifest。新M4教师缺少已完成标签时明确报错。

## 每轮顺序和五次完整对战

一条命令串行执行以下流程，每个训练轮／诊断／对战阶段各用独立子进程；训练轮内的追加标签搜索使用多worker：

1. 当前冻结教师采集200局并保存自然终局。
2. 将真实决策的3份追加搜索作为独立任务，8个CPU worker重放并推进搜索树；单GPU owner集中合批推理，完成本轮M4标签。
3. 评估更新前本轮与近期留出loss，训练100步，保存checkpoint与更新后loss、来源统计。
4. 对固定256局面测试集运行两组固定种子的S1024/N1诊断，与已完成的16500参考结果比较；按前中期／后期记录动作变化率、根访问JSD、高访问动作排序及同模型跨种子波动。
5. 在第2、4、8、12、16轮，完成对冻结16500起点的100-pair完整搜索对战，然后汇总趋势并继续训练。

| 对战节点 | 学生累计步数 | 主要用途 |
| --- | ---: | --- |
| 第2轮 | 16700 | 观察新旧标签混合过渡期 |
| 第4轮 | 16900 | policy池刚全部换为M4 |
| 第8轮 | 17300 | 观察换池后的持续变化 |
| 第12轮 | 17700 | 检查中后段趋势与退化 |
| 第16轮 | 18100 | 最终观察点 |

每次100pair／200局，总500pair／1000局。双方全程native S1024/N1，根噪声关闭、温度0，同一开局交换先后手；沿用现有终局／循环裁定机制。五个节点使用共同的100个独立开局种子，训练采集和决策测试集不使用这组种子。

统计保留胜／和／负、得分与以pair为单位的95%bootstrap区间，同时计算相邻节点得分差的配对区间。由于五次复用相同开局，不把它们合成500个独立pair来缩窄区间。100pair主要用于趋势筛查，单条训练轨迹与五次观察不足以确认普遍收益；若出现关键改善，再用新的独立开局确认。任何评测得分均不触发模型回滚或训练门控。

固定256局面诊断只衡量决策变化及搜索波动，不换算胜率。每轮`current`留出使用M4；`recent`按教师使用原单次或M4；`offline_fixed`、`online_fixed`保持原历史目标。不同目标口径的policy KL不宜直接横比，value MSE仍使用原终局标签。

## 执行、恢复与预计时间

从仓库根目录启动；中断后使用**完全相同的命令**恢复，无须另加`--resume`：

```bash
conda run --no-capture-output -n splendor env PYTHONPATH=src OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  python -u -m splendor.iteration_suite \
  --config configs/entity_attention_v1/iteration_avg4_behavior_20261009.json
```

`Ctrl+C`停止本次子进程及其进程组。行为采集按已落盘对局恢复；多进程重标注按每个已完成根原子保存任务结果，恢复只调度缺失任务；每64个完成任务报告进度，再组装原repeat分片与每局均值；训练恢复模型、AdamW、采样RNG及账本；完整对战按已完成pair恢复，诊断按已完成根恢复。正式配置每100训练步存checkpoint，若在本轮100步完成前中断，尚未保存的训练步骤会重算；已保存的采集和标签无需重做。已完成阶段自动跳过。已启动的数据生成配置、种子、模型、标签和相关搜索代码必须保持一致。

沿用采集8个search worker、总200个活跃游戏、microbatch64、推理batch200及原CUDA Graph桶；重标注使用8个CPU搜索worker、总256个活跃根（每worker最多32个）、worker microbatch64、共享槽2、GPU batch最多200、owner单缓冲、FP32 eager。每个worker只缓存最近2局重放请求，主进程按8局组装标签；标签均值LRU最多1024局，回放缓存4GiB。只有owner持有GPU模型，worker不初始化CUDA；一轮标签共用同一组worker，搜索完成后清理进程和共享内存。每轮结束退出子进程回收模型、树和缓存。按用户要求，此分支**不设置硬RAM上限或磁盘门槛**，记录阶段资源与进度；旧BCD配置的16GiB上限保持原适用范围。

按旧200局采集约7–9分钟、额外四份标签约28分钟估算，复用行为并追加三份约21分钟；16轮采集、标签和训练估计8–10小时，五次100pair对战另约1.5小时，决策诊断额外几分钟。建议预留**10–12小时**。这是原单进程版本的旧实测外推；多进程版真实整轮吞吐尚未测出，不承诺按worker数量提速，实际时长由首轮记录校正。

历史记录：最初停止在115局时做过一次性配置迁移，当时原命令保留115局并补采剩余85局，随后使用多进程追加标签；起点、训练状态、采集manifest和已有NPZ的SHA均保持不变。原准备快照保存在`runtime/entity_attention_avg4_behavior_20261009/before_pool_switch/`，迁移记录见[pool_migration.json](../../artifacts/entity_attention_avg4_behavior_20261009/pool_migration.json)。此迁移只适用于尚未生成标签或训练的停止状态，不放宽已有标签与训练的恢复校验。

只检查准备状态可在上述命令后加`--prepare-only`，不会开始训练。
