## 串行边界

队列入口：

```bash
bash scripts/run_attention128_auxiliary_queue_20261024.sh
```

本任务验证完成后将该等待队列挂在后台，实际身份见`launch.json`。不要重复启动第二份队列；`queue.lock`拒绝并发队列。状态文件在同名runtime的`state.json`，结束／失败／中断时在本目录保存`execution.json`。

队列**阻塞等待前驱的`chain.lock`**。当前监督进程在训练、选点及两组对战期间始终持有此锁，最后提交execution／summary后才释放；等待不轮询训练步数或GPU。锁释放后还必须通过完整性校验：最新会话成功`complete`、训练完成、选中模型内容匹配、greedy1000pair与搜索500pair均passed、实际局数完整且无工程失败。训练子进程退出、保存final、早停触发或一组对战完成都不足以推进。

任一组失败／被用户中断，整个后续队列停止，不自动重试或启动下一组。恢复时先按需恢复失败的前驱；再运行同一队列入口，会验证并跳过已经成功完成的后继组，或用各自既有恢复点续跑。若等待中的队列被停止，不向当前用户拥有的前驱发送信号；队列只转发中断给自己启动的子任务。

三个独立脚本均支持`prepare`、`run`（默认）、`train`和`status`；它们本身是单组完整实验入口。为保持此次串行约束，应由上述队列启动，而不要并行手动运行三个脚本。

## 实现、兼容性和验证

三个8行Python包装器共用[run_experiment.py](run_experiment.py)，复用原实验的训练→选点→两组评测与恢复机制；每组独立配置、源码／native／牌池快照、输出和模型身份。只改变要求的辅助开关及44k数据范围，其余预设逐字段核对。

仅policy组现在不注册短期value头，不生成其标签、不计算其loss／覆盖／梯度诊断；因此不依赖被关闭任务的根W统计。原已实现的仅value／双辅助损失计算与旧checkpoint权重兼容。新模型配置的`predict_shortterm_value`默认true，旧模型未保存该字段仍严格加载。初始化仍消耗原短期头所需随机数后丢弃关闭头的参数，使policy-only与双辅助的对手头初始化逐位一致，同时原主干／短期value初始化逐位保留；关闭头不进入训练模型或常规推理。

采用最新轻量保留形式：逐步`training_metrics.jsonl`、小型参考身份和batch SHA，不写两份`.bin`／`.steps.jsonl`或重复会话metrics。原NPZ、主标签、整局split只读；104k两组共用原冻结池清单，44k重建原R21–R31清单。

[tests.xml](tests.xml)：90项相关回归通过，包含开关／参数缺失、标签跳过、梯度、固定初始化、精确AdamW/RNG恢复、完整留出与选点、实际三组配置，以及锁未释放时不推进、完整结束校验、三组调用顺序、失败后停止。初次准备发现文件名`queue.py`遮蔽Python标准库，已改名`serial_queue.py`；首轮测试仅因准备未完成缺配置而失败，原记录保留于`initial_tests.xml`，重新准备后90项全部通过。

[cpu_validation.json](cpu_validation.json)：每组3局真实历史轨迹、一次CPU更新与严格重载，各3个S8N1原生根（每根总8，合计9根／72模拟），推理辅助头调用为0；与当前原始initial.pt的主干／共有辅助参数逐位一致。没有抢用当前任务GPU，没有在当前任务结束前执行新增正式训练或对战；小规模检查不产生棋力结论。验证与冻结身份见`verification.json`。
