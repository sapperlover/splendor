## 不变的实验设计

- 原64根与原分组、动作索引逐项相同：32根比较根S1024访问前二；另一组为28个搜索／Policy Greedy首选冲突＋4同选控制，控制不计排序指标。
- 原R43 checkpoint、根部那一次S1024搜索、单搜索世界子节点Value、根Q、根实际访问首选全部复用冻结身份，没有重新挑动作或重新搜索根标签。
- 初始隐藏世界种子、抽样器、后验和bootstrap种子相同；同一根／world的两动作分支及Greedy／S1024两实验从完全相同的完整世界开始。
- 每动作先32份配对世界，不确定则补到128；沿用五类配对收益差的Dirichlet(0.5,…,0.5)后验、95%区间和20000份后验抽样。补样决定依本分支新的32份结果重算，不能直接套用Greedy分支补样名单。
- 排序准确率、差值相关性、经验／后验错选收益损失、同选控制排除、截断处理、固定32份及自适应双面板、400玩家回合上限和全部回放核验规则均保持。
- 仍为CPU FP32 eager、2线程、128个活动分支。GPU有已有服务占用，本分支没有切换设备或处理该服务。

配置一致性由专题测试逐项比较，当前计划见 [plan.json](plan.json)。它包含父计划、父统计实现、根搜索证据和本驱动的SHA身份。

## 唯一策略变化

强制执行A／B首步并折叠单候选强制选择后，每个后续多候选决策都由当前行动方的冻结R43执行 **native S1024/N1、c_puct1.5、根噪声0、T0、fold forced phases、transition cap512**。单候选决策直接执行，等价于原搜索返回的零模拟强制选择，不把它算作搜索决策。

实际续局世界的牌序固定；每次搜索仍只接收当前行动方的safe DecisionRequest，独立重建自己的搜索世界。新增搜索随机种子域38500000，按根、配对world、行动方派生，两动作分支共享各行动方的base seed；既有公开请求哈希进一步派生每次搜索世界种子。首步的A／B仍是原比较对象，不由新续局搜索替换。

逐个决策检查模拟数1024、N1、访问总数和无根噪声；逐臂保存搜索决策的动作序列位置、实际模拟总数及搜索seed。最终回放再核对每个非强制后续决策确实有搜索覆盖，汇总实际预算。自然终局才给z；工程未终局仍为null，不改算和棋。

真实对局推进使用现有Python fast引擎，搜索使用现有native批量后端；两规则实现的差分回归属于本次20项有限测试。这样可以直接从当前行动方构建safe请求，保持隐藏信息边界。参考收益现在来自双方S1024续局，比Greedy分支更接近根Q的搜索策略，但单棵根树估计与跨世界完整续局仍不同，不能把剩余误差全部归因于value。
